# The Back Room — project notes for Claude

Read this first in any session that touches this repo. It is the single place the
state of the project lives; update the **Status** section when something changes.

## What this is

A Backrooms-inspired liminal-horror adventure for **D&D 5e (2024 rules)**, levels 5–8,
2–3 sessions, shipped as an installable **Foundry VTT v14** module (dnd5e 5.x+).
The non-negotiable goal, inherited from v1: the finished campaign installs in Foundry
from a manifest URL and plays from the Adventure compendium with no manual assembly.

The design is in **`docs/the-back-room.md`** (arc, rooms, mechanics, Foundry concealment), **`docs/corridor-pool.md`** (the eight Corridor places — the spec the maps are built from; wins over the design doc on conflicts) and **`docs/tropes.md`** (raw trope lists) (exported from the Claude doc
"The Back Room — Adventure Structure"). Summary: the party beds down in a tavern back
room and never leaves it; five fixed rooms (Five-Room Dungeon beats, with Pointy Hat's
theme/gimmick/motive/clues overlay) threaded through a random-door **Corridor** pool
of eight in-between places; the central escalating gimmick is misremembering; the
antagonists are the **Remnants** — each player's first-ever D&D character, as the
table misremembers them. The doc has the room-by-room content, Corridor rules, the
Remnant template and fallback Remnants.

## Pipeline (kept from v1)

```
tools/maps.json  ──┐
tools/journal.py   │   python3 tools/build.py   →  src/packs/*.json
tools/actors.py    ├──────────────────────────→  npm run build:packs → packs/ (LevelDB)
tools/matt.py    ──┘                              npm run validate  → link/asset check
                                                  npm run package   → dist/module.zip
```

- `tools/maps.json` is the scene contract: per scene key → `file, w, h, walls[], lights[],
  notes{}, rects{}, start, darkness`. Walls use `{c:[x0,y0,x1,y1], move, sight, light, sound,
  door, ds}`; lights `{x, y, dim, bright, color, alpha, anim}` with dim/bright in feet.
- Grid is **100 px per 5 ft square** everywhere.
- Scene automation is **Monk's Active Tile Triggers** (required dependency, 14.01+),
  generated by `tools/matt.py`. v1's door-teleport, looping-room and lights-out tiles
  are the right primitives for the Corridor rules ("no door leads back", visit counter).
- Release: push to `main` runs Validate; a GitHub release tagged `vX.Y.Z` runs the Release
  workflow, which stamps module.json and attaches `module.json` + `module.zip`.

## Maps: Dungeondraft, not generated

v1's `tools/maps.py` drew the maps procedurally. **v2 maps are built in Dungeondraft**
through the Dungeondraft MCP bridge (the `dungeondraft` tools, running on the Windows PC
on the LAN; file transfer to/from the Mac via `dd_download` / `dd_upload`). Then:

1. In Dungeondraft, campaign **`BackRoom`**, one map per scene. `export_dd2vtt(ppi=100)`.
2. `dd_download` the .dd2vtt into `~/Claude/Projects/the-back-room/dd2vtt/` (gitignored).
3. `python3 tools/import_dd2vtt.py <key> dd2vtt/<Name>.dd2vtt --darkness 0.6 --name "..."`
   writes `maps/<key>.webp`, `maps/thumb-<key>.webp` and the `maps.json` entry (walls,
   doors, lights converted to px). Notes/rects/start/darkness survive re-import.
4. Add keyed notes (`notes`) and named `rects` to the entry by hand. `tools/matt.py`'s docstring lists the rect
   names each scene needs (pool copies: door1/door2[/door3], arrive1/arrive2[/arrive3], xdoor; etc.). Pool
   copies share one `maps.json` entry under the place key (`c1-stairwell`); `build.py` makes the a/b/c scenes.

`tools/maps.py` is obsolete for v2 and can be deleted with the v1 content.

Known trap (seen 2026-10-25): the Foundry *Universal Battlemap Importer* module creates
the scene but silently fails to write the image on v14 (deprecated FilePicker upload).
Irrelevant to the module build (we ship our own webp), but if you test a .dd2vtt by
importing it into a world directly, copy the image into `worlds/<world>/maps/` yourself.

same art, one detail different, hidden from the nav bar, named blandly. ~20 Foundry
scenes from 8 maps. The random-door tile picks among copies, excluding the one just left.
`import_dd2vtt.py` needs a `--copies` option (or run it per key) and `build.py` needs
copies sharing one image file.

Automation primitives (MATT): random-door → pool copy; visit counter on Corridor entry
(cue table: 1–2 nothing, 3–4 sound, 5–6 glimpse, 7+ Remnant); X door appears when the
previous room's condition is met; Room 3 segment doors + loop break; Room 4 exit; a
GM-only **Reveal** tile that restores fog and real scene names for Room 5.

## Conventions

- Python 3, Pillow/numpy for tools; `pip install pillow numpy scipy`, `ffmpeg` for audio.
- Journals are **Monk's Enhanced Journal** entries, and the journal folder is a **Campaign Companion**
  campaign (both are required dependencies in module.json). `journal.py` still writes plain (name, pages)
  content; `build.py` turns it into MEJ entries: one `text` page per entry with
  `flags["monks-enhanced-journal"] = {type, ...defaults, ...data}` and the entry flag `{pagetype, img}`.
  Types used: Rooms 1–5 and the eight Corridor places = `place` (attributes size/inhabitants, relationships
  to the people in them); NPCs = `person` (attributes profession/voice/faction, `actor` link {id,uuid,name,img});
  The Cover = `encounter` (`actors` keyed by actor id); The Remnants = `organization`; Follow the X = `quest`
  (`objectives` keyed by id: content/available/status/done/required); guides, rules, Cast and handouts =
  `journalentry`. Relationships are `{id, uuid:"JournalEntry.<id>", relationship, hidden, role?}` keyed by the
  other entry's id. Sessions 1–3 are the companion's native page type `mej-campaign-companion.session`
  (`system.recap`, `system.gmNotes`, `flags[CC].session`). The campaign = folder flag
  `{campaign:{ownershipDefault:"none", defaultTimelineId}}` plus a shipped portal entry (page type
  `mej-campaign-companion.campaign`, flag `campaignPortal:true`, NO MEJ pagetype flag on the entry or the
  companion's guard refuses it) and a `— Timeline` journal (no pages, `flags[CC].timeline.timepoints`,
  `core.sheetClass`). Verified in World B 2026-10-27: Place/Person/Encounter/Organization/Quest/Session sheets
  open, Hub scopes to the campaign, portal and timeline import. The companion auto-links entry names on import.
- GM text in `<p>`, read-aloud in `<blockquote>`, keyed areas as `A1.`-style headings; handouts in their own folder.
- Never stat the Remnants as monsters; they are NPCs (see design doc).
- One misremembered trope per Corridor scene. Two is a joke.

## Vistas (roleplay scene images), pipeline settled 2026-10-26

Style: hand-drawn cartoon fantasy, matching Dungeondraft. Generated on the Mac with
**Draw Things** (SD 1.5 base, no LoRA yet) driven over its HTTP API (port 7860) from a
Chrome tab at http://127.0.0.1:7860/ via the Chrome tools.

- **Pipeline:** three.js scene (`/home/claude/vista/<scene>-ink.html`, rendered with
  `node render.mjs <file> out.png 768 512`) → ink/toon render → **img2img, strength 0.8**,
  style block + one content sentence, 3 seeds → pick one.
- **Style block:** `hand-painted fantasy illustration, tabletop RPG art, storybook, soft ink
  outlines, flat warm colours, painted shadows, parchment texture`. Negative: `photo,
  photorealistic, 3d render, cgi, blurry, text, watermark, people, person, figure, deformed, lowres`.
  DPM++ 2M Karras, 20 steps, cfg 6, 768×512.
- **ControlNet does NOT work over the HTTP API** (no way to pass a control image; the
  `controls` field needs `enabled:true` but still has no image). Verified: results were
  pixel-identical to txt2img. Don't retry. img2img honours `init_images` + `strength`.
- **Getting images back:** Draw Things writes every API generation to `~/stablediffusion`
  (name = prompt + seed). Copy to `~/Downloads/backroom-vistas/<scene>-<variant>.png`.
  Browser downloads are blocked after the first; don't use them.
- **Sending images in:** a `<input type=file>` on the API page + the Chrome `file_upload`
  tool with a path under `/home/claude/vista/`; a FileReader puts the base64 in `window.__depth`.
- Picks so far (in `~/Downloads/backroom-vistas/`): Room 4 reading room = `reading-room-ink80-1003.png`
  (img2img from the ink render, strength 0.8); Room 1 back room = `backroom-s1001.png` (strength 0.8,
  drifted from the render but the best picture); Room 2 common room = `common-room-s2001.png` (strength 0.75,
  seeds 2001+ with a people-free negative: `people, crowd, patrons, bartender, silhouette, cloaked figure,
  character, portrait, face, hands`). Room 3 corridor = `corridor-s3003.png` (strength 0.6: at 0.75 SD turned the corridor into rooms;
  long one-point views need 0.6). Lesson: strength 0.6 for corridors, 0.7–0.75 for rooms, 0.8 only when
  the picture matters more than the plan; always add the people-free negative for empty rooms.
- The Cover cavern = `cover-cavern-chatgpt.png` (generated by the user in ChatGPT from the prompt in the session
  notes; SD 1.5 could not stage six monsters in one frame). All five fixed scenes now have a vista.
